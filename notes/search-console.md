# Verifying archeus with Google, Bing and the rest

Neither host is verified. Everything below is a one-time setup done in a browser
and at a DNS registrar; nothing here is a code change, which is why it is a note
and not a module.

## Use a Domain property. Not a URL-prefix one.

This is the decision that matters and it was already got wrong once here.

| | Domain property | URL-prefix property |
|---|---|---|
| Verified by | one DNS TXT record | a meta tag, an HTML file, Analytics… |
| Covers | the apex **and every subdomain**, http and https | exactly the prefix typed, nothing else |

A URL-prefix property on `claudectl.space` reported on `claudectl.space` and
**nothing** on `docs.claudectl.space` — 28 of 46 known URLs simply absent, with no
error to say so. The manual is the larger and more linkable half of what archeus
publishes, so that is most of the site invisible.

One Domain property on the apex covers both. Add a second URL-prefix property for
`docs.` **as well** if you want per-host charts side by side — the two are not
exclusive — but the Domain property is the one that must exist.

## Google

1. [search.google.com/search-console](https://search.google.com/search-console) →
   **Add property** → **Domain** → the bare apex, no scheme, no `www`.
2. It gives one record. At the registrar:

   ```
   Type   TXT
   Name   @            (the apex itself — some registrars want the bare domain)
   Value  google-site-verification=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
   TTL    3600
   ```

   Keep any existing TXT records at the apex. A second TXT record is fine; a
   replaced SPF record is an outage.
3. Verify. DNS is usually minutes but the record is checked again periodically —
   **never delete it**, or the property silently unverifies.
4. Submit both sitemaps (they are separate hosts, so both are needed even under a
   Domain property):
   - `https://claudectl.space/sitemap.xml` — 19 URLs, generated by `www/app/sitemap.ts`
   - `https://docs.claudectl.space/sitemap.xml` — 29 URLs, generated by MkDocs

No `verification` block goes into `www/app/layout.tsx`. DNS is the mechanism; a
meta tag would be a second thing to keep in step, and it only ever verifies one
host anyway.

## Bing (and therefore Yahoo, DuckDuckGo, Ecosia)

Bing Webmaster Tools **imports from Google Search Console** — one OAuth click, and
it carries the verification and the sitemaps across. Do that rather than adding a
second TXT record.

If importing is not wanted, the manual route is a TXT record
(`MS=msXXXXXXXX`) or an `msvalidate.01` meta tag. Yahoo has served Bing's index
for years and has no separate console.

## IndexNow — worth the ten minutes

Bing, Yandex, Seznam and Naver accept a push notification that a URL changed,
instead of waiting for a crawl. One key, one file, one HTTP GET per deploy.

1. Generate a key (any 8-128 hex chars, e.g. `py -c "import secrets;print(secrets.token_hex(16))"`).
2. Serve it at the root of **both** hosts as `<key>.txt` containing the key and
   nothing else: `www/public/<key>.txt` and `docs/<key>.txt`.
3. Ping after deploy:

   ```
   https://api.indexnow.org/indexnow?url=<url>&key=<key>
   ```

   A sitemap-wide ping is not a thing; it takes a URL list (`POST` with a JSON
   body of up to 10,000 URLs). Google does not participate.

Not wired up yet — it needs a key that is a secret-ish value and a deploy hook on
two projects, and it is worth nothing until the sites are verified and indexed.
Do it after the domain move, not before, or the key file moves with the host.

## The rest

- **Yandex Webmaster** — a separate TXT record. Worth it only if the traffic
  justifies it; for a Windows-first developer tool it probably does not.
- **Google Analytics / Tag Manager** — deliberately absent. The sites ship no
  third-party script at all, which is most of why they are fast and all of why
  they need no cookie banner. Search Console gives query and impression data
  without any of that.

## What verification will and will not tell you

It will tell you which queries the site appears for and where. It will **not**
make it appear — the prior lesson here is exact: a three-day-old domain with
perfect technical SEO returned zero Search Console results, and the signal, when
it came, came from the entity graph (`sameAs`, the FAQ disambiguation, the
repository and profile corroboration) rather than from any tag on any page.
`BACKLINKS.md` in the growth repo is the other half of this, and it is the half
that moves.
