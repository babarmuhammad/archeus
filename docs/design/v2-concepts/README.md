## How to read the concepts

Perspective illustrates an immersive spatial model; a still does not demonstrate camera motion. Opening frames are an entrance composition, not a claim that opening the UI starts work. Static light in an image is not permission for bloom, breathing, rotating cages or loops. The architecture's meaningful glyphs, recorded links, typed state colours and zero-idle-motion rules take precedence.

Generated artwork may add extra anonymous bodies, material reflections, coloured project dots, invented fixture project names, landscape/miniature interiors, speculative edge tiers, button wording or text errors. None becomes an architecture decision. Production uses only recorded objects and loaded tiers; no unlabelled decorative population, office/world metaphor, physical diorama, translucent/glass panel, default unclear-tier legend, inferred causality or fake tool output. Every delivered view received a corrective image-generation pass to remove physical-world imagery and strengthen software-data semantics. Initial exploratory board is not part of the final deliverable.

Phone is a form/structure concept: final action rows, fixed-bar outcome labels, five root tabs, pushed page without tabs and approved dense typography follow X.3/X.5. A static locator is optional LS-Q8, not a decided change to the below-600 px graph rule. No generated phone layout establishes hit geometry or contrast. Future people, Ideas research, Explain/Fix and liveness require their own contracts and are not shown as shipped functionality by this document.

Images were exported as PNG from the generator's returned image bytes, reducing resolution only where needed to stay **strictly below 1,000,000 bytes each**. No source image was opened from an account home. The image service automatically keeps its own generated-image cache outside this worktree; that behaviour is tool-managed, and no cache file was inspected or modified. Temporary export sources are removed from this deliverable.

## Visible concept limitations

- Entrance's extra generator-added aggregate counts are inconsistent with its headline; use only the three-stage reveal composition. Canonical counts come from LS-2 / Q17, never these annotations.
- Some glyphs and coloured project markers still differ from the canonical kind/state table. Reuse `encoding.ts` and presentation tokens in implementation; do not copy generated glyph semantics.
- Mission result/edge wording illustrates a fixture. It does not establish P21 provenance, tool-output availability, passed checks or actual execution progress.
- Phone scene is illustrative: approved E density, no tabs on pushed pages, exact consequence labels and measured touch geometry remain authoritative. No estimate in generated art constitutes a duration contract.
- A still cannot certify idle parking, reduced-motion behaviour, contrast, typography sizing or camera performance. Those remain the named prototype gates.
- In 04, the generated phase list is not S-17's phase-column timeboard; the architecture retains the actual board. In 06, generated item counts and a project's “Verified” badge are not an added project-state/data contract. In 07, repeated mission/idea labels across hulls illustrate layout only; production uses one recorded membership. In 08, the generated footer wording must be replaced with Q17's “Not stopped · accepts new work”.
