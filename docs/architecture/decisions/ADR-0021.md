# ADR-0021: Feasibility gate: provider terms for automated headless use of subscription accounts

**Status:** OPEN · **Date:** 2026-09-23

## Decision

Before implementation proceeds past P0, the user confirms whether automated headless use of subscription accounts, and rotation across several subscriptions, is permitted by each provider's terms. The design runs unchanged with API-key accounts.

## Why

The migration kit's feasibility doctrine: a fully sketched plan may still end in "don't". The router and multi-account features depend on this answer.

## Alternatives

Assume permitted; restrict V1 to API keys.

## Tradeoffs

Uncertainty until answered.

## Consequences

If not permitted: default accounts to API keys, keep subscription accounts for interactive/manual sessions only.
