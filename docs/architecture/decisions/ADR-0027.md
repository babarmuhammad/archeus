# ADR-0027: Identity and operational presence — the mark, the orbit and the control surface

**Status:** DECIDED (user directive and approval, 2026-09-30) · **Date:** 2026-09-30 · Implementation owner:
P19.5 · Rulebook §6, §8, §9

## Decision

1. **The mark in the product.** The credited mark (the gold A pierced by its orbit, Federico
   Coscia; `docs/assets/logo.png`, `wordmark.png`) appears as a monochrome `currentColor` glyph in
   the shell header beside "Archeus", and as the app icon, favicon and PWA icons (the dark tile
   tier), replacing the current diamond, which is the Attention symbol. Nowhere else — no repeated
   logos, no spinning logo.
2. **Presence.** The orbit's node is the system presence indicator: neutral when idle,
   `state-active` while executions run, `state-attention` when something needs the user, hollow
   when disconnected. It travels once round the orbit per batch of activity (≤ 900 ms, ≤ 1 per
   5 s) and parks; reduced motion shows the colour only. The favicon shows the same three states
   statically. The strip sentence is the text equivalent.
3. **Operations strip** (one line in the shell, every page): mark + "2 running · 1 needs you ·
   3 clients" + freshness + Pause all (when Core provides it) + emergency stop behind a
   confirmation, with its engaged state (when Core exposes it). Every number links to its list.
4. **Now is the operational command surface**, at most seven blocks, in this order: state
   sentence; needs you; happening now (halo, pulse, activity chip, fraction); recent real output;
   since you last looked; upcoming (when Core provides schedules — until then approved/planning
   missions); recent decisions; a compact **live map** (bounded graph of live work only, ≤ 40
   nodes, ≥ 1000 px); the conversation. Lists remain the authoritative control mechanism; the map
   is the overview.
5. **State sentences, never greetings**: "2 missions are active. 1 approval needs you.",
   "Nothing is running.", "Archeus is waiting." — derived from counts; never invented activity,
   never time-of-day personality.
6. **Control-room character through information, not decoration**: persistent awareness, live
   state, attention, evidence, history, context and impact. No avatars, office metaphors, stations,
   HUD chrome, decorative gauges or idle life.
7. **Attention model** (after Vicoa R2): informational · working · awaiting you · offline · error ·
   recovery are distinct; the badge counts only genuine actionable attention (`/v1/attention`).

## Why

brand-study: "the app has no mark at all"; the backdrop rule "bounded, driven by real state, and
it stops" moves from a background to the orbit. SP 886-891 ("ARCHEUS ● ACTIVE"), PROMPT 1299-1382
(presence, upcoming work, recent decisions), R1's agent strip and "representation is the status",
R2's badges and resume actions, and the observability-designer "7 ± 2 panels" rule.

## Consequences

Core dependencies (ADR-0030): Pause all, readable emergency-stop state, schedules. Client-only:
mark, orbit, favicon, strip counts, state sentences, live map, recent decisions (approximate).
