# ADR-0012: Knowledge as typed items with lifecycle in SQLite; no vector store in V1

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Knowledge is `knowledge_items` (typed, scoped, with provenance, confidence, validity windows, supersession, state) plus generic `relations` with EXTRACTED/INFERRED/AMBIGUOUS tiers. Retrieval is BM25 (reusing the current scorer) + anchors + relation expansion + recency, behind a search interface. No embeddings in V1.

## Why

Current retrieval quality is adequate with lexical + structural signals; embeddings require a model dependency or a network call per item. Lifecycle fields are what stop stale knowledge, and they are missing today.

## Alternatives

Cognee as the memory runtime; vector-first memory; keep graph.json.

## Tradeoffs

Semantic paraphrase matching is weaker until vectors arrive.

## Consequences

Search interface is swappable; revisit when retrieval misses are measured.
