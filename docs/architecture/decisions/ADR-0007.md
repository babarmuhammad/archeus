# ADR-0007: Policy engine as data + code, enforced first by capability removal

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Policies are versioned rules over a closed set of action classes across scopes GLOBAL to ACTION, combined strictest-wins with locked rules (DENY always locked). Enforcement: (1) Core before its own actions; (2) the execution environment has only the capabilities policy allows (no push credentials, sandbox flags, tool allowlists) and Core alone performs push/deploy/external communication/merge; (3) a per-tool hook that fails closed for Archeus executions. Approvals are bound to action hashes, single-use and expiring.

## Why

Hooks alone are bypassable (shell indirection), unavailable on some harnesses and fail open today. Policy in a prompt is untestable (Munder Difflin). Capability removal is the only guarantee that survives a clever agent.

## Alternatives

Hooks-only enforcement; prompt-level policy; harness permission settings only.

## Tradeoffs

Some harnesses become ineligible for some tasks; Core must implement push/merge itself.

## Consequences

Router uses a harness `enforcement` capability. Canonical actions are what users approve.
