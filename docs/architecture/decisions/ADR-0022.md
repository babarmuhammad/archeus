# ADR-0022: Archeus's own model calls run on any capable harness

**Status:** DECIDED · **Date:** 2026-09-25

## Decision

A tool-less structured call (plan §31.4: knowledge extraction, lessons, generation, brain, planner, review judge) is harness-generic. It is performed by a harness adapter's `call()` operation, offered by every harness that declares the `headless` capability: the adapter builds the invocation, keeps it read-only (no write or exec tools, in that harness's own flags), makes it ephemeral (it creates no session the user sees in that harness) and requests structured output its own way. Structured output is a Core requirement, not a harness flag: Core validates every result against the schema (ADR-0006) whether the adapter asked natively (`structured_output: native`) or inside the prompt (`structured_output: prompted`), so no `headless` harness is eliminated for lacking a schema flag. A call is routed like other work, as RouteDecision subject `archeus_call` with its purpose; the user's choice of harness and model for these calls is a routing preference (or, when the user marks it required, a constraint) scoped to that subject, not a routing rule. Until P10, a pre-router election recorded as a RouteDecision applies: the user's choice if that harness is installed and `headless`, else Claude Code if installed, else the first installed `headless` harness; the account is the elected harness's (for Claude Code, legacy `rotate.elect()` + `quota.reason()`). Model ids and effort levels are harness vocabulary: a model is valid only as an offer of the target account, an effort only if the target adapter declares it, and one that is not is dropped, never translated.

## Why

Since 2.8.0 the current product builds memory, lessons and generated files on pi with a locally hosted model when Claude Code is absent (`memory.headless_harness`, `headless_argv`, `headless_harness_model`). The plan's wording ("one headless `claude -p` call") and its pre-router account source would regress that the first time V1 makes a real call (P6).

## Alternatives

Claude-only calls until the router exists (P10); every call as a Task and Execution.

## Tradeoffs

Prompted structured output fails validation more often, so ADR-0006's retry-once-then-ask applies. A weaker local model produces weaker INFERRED knowledge, which provenance must show (harness and model on the RouteDecision the item cites).

## Consequences

No new entity: a call has no Session and no Execution; its usage is ledgered against its RouteDecision. `llmcall.build_headless_args` becomes the claude_code adapter's call argv and `llmcall.run_headless` stays the shared runner. The pi adapter is no longer deferred for calls or user sessions; its tool-using execution stays deferred (`enforcement: none`). Amends plan §31.4, execution-architecture §3, resource-router §3, domain-model §8.
