# ADR-0015: Conversation model: one primary conversation plus mission threads with live cards

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Each user has one persistent primary conversation (Now) and each mission has a thread; messages acting on a mission are linked into its thread. Replies carry typed live cards bound to domain objects. Archeus can raise Challenge blocks when evidence conflicts with the request.

## Why

Keeps conversation the primary interaction without making it the only way to see state; cards are live views so they never go stale.

## Alternatives

Many ad-hoc chats (ChatGPT style); chat per project only.

## Tradeoffs

Cross-linking logic between threads.

## Consequences

Message model has `cards[]` and `links[]`.
