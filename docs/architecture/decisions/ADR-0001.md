# ADR-0001: Modular monolith control plane, grown beside the current package

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Archeus Core is one long-lived Python process containing all domain modules (missions, planning, context, knowledge, policy, routing, execution, verification, automation, world) behind explicit in-process interfaces. It lives in a new top-level import package `archeus/` next to `claude_sessions/` and grows by strangling the legacy app.

## Why

Single user, single machine, many tightly-coupled domains that share one transactional store. Microservices would add network failure modes, deployment and auth between services with no scaling benefit. A new package (rather than refactoring `claude_sessions/` in place) keeps the legacy app shippable, and a distinct import name removes the hazard where two distributions install the same `claude_sessions` package and uninstalling one deletes the other.

## Alternatives

Microservices per domain; refactor `claude_sessions/` in place; rewrite in another language.

## Tradeoffs

One process is a single point of failure (mitigated by e-stop without Core and by reconciliation on restart). Two packages coexist for a while.

## Consequences

Module boundaries are enforced by an import-graph test (`core` never imports `api` or `clients`). Execution nodes are the only separately deployable part, and only later.
