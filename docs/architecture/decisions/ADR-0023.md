# ADR-0023: A user's own session resumes and hands off through its harness

**Status:** DECIDED · **Date:** 2026-09-25

## Decision

A user's own session (an Execution in mode `interactive_attached` or `manual`, including the sessions migration imports) is resumed by the adapter of the harness its Session belongs to, from what that Session recorded: harness, account, `provider_session_ref`, and the model and effort in that harness's vocabulary. Settings and defaults of another harness are never passed to it (ADR-0022's vocabulary rule). Handing a user's session to another harness or account is a session hand-off: the source Session is not changed; the context is transferred as a Core-rendered hand-off artifact; a new Session records `handoff_from_session_id`; a `session.handed_off` event is written; the target is chosen by the user among the installed harnesses that declare `interactive`, the source's own harness first; and the target adapter's `handoff()` delivers the artifact through a channel that harness has (the current product uses an opening message pointing at it, the one channel every CLI it supports shares). For an execution inside a mission the artifact is the checkpoint (ADR-0004). For a session outside any mission, where Core holds no mission state, the artifact is derived from the transcript, the one stated exception to ADR-0004's "checkpoints, not transcripts".

## Why

Since 2.8.0 the current product resumes pi and Codex sessions on the model and thinking level they recorded, where it used to send Claude Code's defaults and pi refused to open them; and hands a session off to any installed CLI, not Claude accounts alone. ADR-0004 and P12 cover hand-off only between executions of a mission task.

## Alternatives

Leave user sessions out of V1 (the retirement gate needs them); wrap every hand-off in a mission.

## Tradeoffs

A transcript-derived artifact is only as good as the transcript and carries no verified mission state.

## Consequences

Session gains `model`, `effort` and `handoff_from_session_id`. The file `.archeus/injected-context.md` is the legacy transfer mechanism, not the contract. P11 owns resume and the adapters' `resume`; P12 owns session hand-off beside checkpoint hand-off. The retirement gate gains hand-off of a session to any installed harness.
