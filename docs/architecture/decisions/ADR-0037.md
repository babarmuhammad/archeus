# ADR-0037: The harness descriptor declares what a harness serves; orchestration never branches on a harness id

**Status:** PROPOSED (the user's directive of 2026-09-30, second orchestration pass, §2, §11; awaiting approval) · **Date:** 2026-09-30 · Implementation: P22 (with the Harness rows) · Extends the P1 adapter contract (execution-architecture §3) · Plan: [ARCHEUS_V1_ORCHESTRATION_PLAN.md](../ARCHEUS_V1_ORCHESTRATION_PLAN.md) A2, C2

## Decision

1. **The P1 adapter contract remains the harness interface** (`discover`, `capabilities`,
   `authenticate`, `start`, `send`, `pause`, `resume`, `stop`, `inspect`, `status`,
   `collect_result`, `call`). No second harness abstraction is introduced.
2. **The descriptor gains facts the orchestration currently has to assume:**
   - `serves` ⊆ {`archeus_call`, `task`, `review`, `session`} — the routing subjects this harness
     can run (pi today: `archeus_call`, `session`);
   - `installed_version`, populated by `discover()` (it is `None` on every real adapter today),
     copied into each decision's snapshot;
   - `pause`: `cooperative | none`;
   - the capability vocabulary gains `browser` (drives a browser; distinct from `web` fetch) and
     `fs_read` (read access distinct from `code_edit`). *(`browser` withdrawn from P22 on
     2026-10-03, see "Amended"; `fs_read` unchanged.)*
3. **Deliberately not harness capabilities:** verification (Core's, independent of the executor),
   patch application to the user's tree (Core merges a verified worktree, ADR-0007), and artifact
   recording (Core's producer record, ADR-0034).
4. **Orchestration code never branches on a harness id.** Routing, application and planning read
   descriptors; a gate fails on a harness-id literal there, with the two legacy seams
   (`archeus/core/ports.py:205`, `archeus/core/routing/usage.py:60`) named as exceptions until P22
   retires them.
5. **The Harness row and `harness.state_changed`** (registered, never emitted) are written by
   discovery in P22, so a harness appearing, vanishing or changing version is an event.
6. **Declarations are verified against the installed CLI** (its own introspection), never
   asserted from memory.

## Why

The contract frozen in P1 already covers execute, stream, cancel, permissions and results; what the
router and the UI cannot see is *which subjects* a harness can serve and *which version* it is —
so "pi can make own calls but cannot execute tasks" lives in the choice of Python class, and
evidence keyed on harness version (ADR-0032 §4) is keyed on `None`. Claude Code must be one
implementation among several, which a descriptor-only orchestration guarantees.

## Alternatives

A new generic "Harness interface" layer (rejected: duplicates the frozen contract); inferring
`serves` from which adapter classes exist (rejected: implicit, invisible to the UI); per-harness
branches in the router (rejected: the pattern this ADR forbids).

## Tradeoffs

Descriptor fields must be kept honest per harness release; the introspection test is the guard.

## Consequences

Amends execution-architecture §3 (descriptor table) and `CAPABILITIES` (`fs_read`; `browser` withdrawn, see "Amended").
No change to enforcement, policy or the process I/O contract.

## Research inputs (2026-10-02, not part of the decision)

The external research of 2026-10 ([../../research/2026-10-external-research.md](../../research/2026-10-external-research.md))
found two inputs for deciding this ADR. The text above is unchanged.
- **XR-2:** what declaring `browser` must require:
  - a policy action class;
  - an isolated profile, never the user's real one;
  - a request-level domain filter (Browser Use's covers navigation only);
  - telemetry off and verified.
- **XR-6:** whether the vocabulary gains a desktop-control word (Windows Harness: UI Automation,
  SendInput, PowerShell).

Both are sequenced as V2-A4 / V2-A5 (plan §31.5).

*Added 2026-10-03:* **XR-12** asks whether the `browser` word itself ships in P22 before XR-2
defines its policy. Today `CAPABILITIES` has no `browser` (`archeus/core/domain/entities.py:835`),
and `IMPLIED` maps capabilities to action classes with no `browser` entry while `web` is ALLOW by
default (`archeus/core/policy/rules.py:22,36`). The options are inert, with an action class, or
deferred, and they are recorded in [../ARCHEUS_V2_ASSISTANT_LAYER.md](../ARCHEUS_V2_ASSISTANT_LAYER.md)
§4. *Decided 2026-10-03: deferred to V2-A4 (see "Amended").*

## Amended (2026-10-03, the user's answer to XR-12)

**`browser` is withdrawn from P22's capability vocabulary.**
- **Its replacement:** the word, its policy action class and its boundary (XR-2: an isolated
  profile, a request-level domain filter, telemetry off) are designed together, in one ADR,
  as a prerequisite of V2-A4.
- **Its consequence:** nothing named `browser` exists in V1 that a harness could declare
  before its policy exists. P22's descriptor work adds `fs_read` and the other §2 facts
  unchanged.
- **Why defer rather than ship it inert:** an inert word needs a guard and a test to stay
  inert, and buys nothing V1 uses.

This ADR remains PROPOSED. The rest of its text is unchanged.
