# ADR-0004: Mission is the continuity abstraction; sessions are infrastructure

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

The user-facing unit of work is the Mission (with Plan, Task, Execution beneath). A Session is a provider conversation bound to one harness and account; it can end, rotate or fail without changing mission state. Continuity across sessions is carried by Core-derived checkpoints, not transcripts.

## Why

Spec §17-18: users should see "the dashboard is continuing", not session token counts. Sessions die for reasons unrelated to the work (limits, context pressure, crashes, account changes).

## Alternatives

Session-centric model (today); agent-centric model (Munder Difflin office floor).

## Tradeoffs

Checkpoints must be derived well enough that a fresh session continues productively; this is tested in the judge (S2).

## Consequences

Account change always implies a new session via hand-off. The UI never lists sessions as the primary object.
