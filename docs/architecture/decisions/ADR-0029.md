# ADR-0029: Visual evidence — deterministic regression and manual visual acceptance

**Status:** DECIDED (user directive and approval, 2026-09-30) · **Date:** 2026-09-30 · Owner: P19.5 (gates),
P23 (acceptance program) · Rulebook §34, §40

## Decision

1. **Deterministic first:** the graph renderer and every registry animation render as a pure
   function of (state, presentation time); unit tests assert frames at fixed `t` (`renderAt(t)`).
2. **Framebuffer reads for the canvas**, not screenshots (a headless canvas/WebGL screenshot proves
   nothing): pixel probes assert halo, hull, focus and edge styles.
3. **Frozen-clock captures** of every surface × {dark, light, forced colours, reduced motion} ×
   {1440, 1000, 390 px} × {idle, working, output, attention, error, recovery, offline, disabled}
   against fixture Cores (the P18 1,000-node fixture and a 12-concurrent-execution fixture);
   diffs reviewed by a person, never auto-accepted.
4. **Computed-style and text gates:** focus ≠ attention; registry-only animation; the idle
   invariant; an innerText read of every page with no raw ids, JSON or hashes in the default view.
5. **Before/after on the real app** (after Munder Difflin R1): every P19.5 change carries both
   captures from a real Core started with the developer launcher.
6. **Every new gate is mutation-verified**: remove the feature, the gate must fail.
7. **Manual visual acceptance** (rulebook §34) is recorded per item with how it was verified
   (tool-verified / needs device / assumed). Emulation never counts as a physical-device check.

## Why

The repository's own lessons ("measure UI bugs, don't eyeball them"; "WebGL screenshots lie
headless"; "read the pages"; "a gate nobody has watched fail is not a gate"); R5's behavioural
judge that must fail on broken code; R7's `renderAt(t)`.

## Consequences

testing-strategy §7 lists the gates; P18's manual checks stay separate and owed.
