# ADR-0049: What a V1 execution inherits from the Claude Code settings sources it runs under — the account home's, the project's and the local hooks, plugins, skills, MCP servers, permissions and CLAUDE.md

**Status:** DECIDED (the user's answer to XR-1, 2026-10-03: option D with an always-on inventory, all three sources in scope, deny by exit code 2) · **Date:** 2026-10-02, revised and decided 2026-10-03 (see "Revision") · Implementation: **P20** (PV-10; verified by PV-19, which needs ADR-0021) · Raised by the external research of 2026-10 as XR-1 · Register: [ARCHEUS_V2_ASSISTANT_LAYER.md](../ARCHEUS_V2_ASSISTANT_LAYER.md) §4 XR-1, PV-10 · Research: [2026-10-external-research.md](../../research/2026-10-external-research.md) F-1 · Reads ADR-0007, ADR-0019, ADR-0021, ADR-0045 §12, ADR-0046, ADR-0047

## Context — what is built

**Evidence tags:**
- **[A]** Archeus code at `0a2a3af`;
- **[CLI]** `claude --help`, v2.1.287;
- **[DOC]** the Claude Code documentation as read on 2026-10-03 (settings, hooks, headless, managed-settings and CLI-reference pages);
- **[I]** inference.

1. **The spawn [A].**
   - The Claude Code adapter starts every execution with `CLAUDE_CONFIG_DIR` set to the account's
     home (`archeus/harnesses/claude_code/adapter.py:127-133`), because the OAuth login lives there.
   - It runs in the execution's worktree, so the project's own `.claude/` directory is present too.
   - It passes `--settings <exec dir>/settings.json`, which holds only Archeus's own `PreToolUse` and
     `PreCompact` hook (`adapter.py:104-125`).
   - It passes neither `--setting-sources`, `--strict-mcp-config` nor `--disable-slash-commands`
     (`adapter.py:117-126`).
2. **Archeus's own legacy hooks already stand down [A].**
   - `base.spawn` sets `ARCHEUS_EXECUTION_ID` in the child's environment (`archeus/harnesses/base.py:303`).
   - The P0.5 hook-environment guard makes `recall_hook`, `worklog_hook` and `memdirty_hook` return
     immediately when it is set.
   - `limit_hook` still records the shared limit latch but offers no rotation (plan §31.1 P0.5 item 3).
   - ADR-0045 §12's cutover marker is a *second*, per-project seam for legacy writers. It is not
     what silences the hooks inside an execution.
   - **What is not covered is everything else in those settings sources:** third-party hooks,
     plugins, skills and MCP servers.
3. **What the CLI loads besides [CLI][DOC]:**
   - **Settings sources.** `--setting-sources` takes `user, project, local`. The documented
     precedence is managed > `--settings` > local > project > user [DOC], and **hook arrays merge
     across sources** [DOC], so every source's hooks run beside Archeus's own.
   - **Managed settings.** Enterprise policy settings and their hooks always apply, whatever the
     other flags say [DOC]. No option below can exclude them.
   - **Headless runs.** Hooks fire in `-p` runs, including `UserPromptSubmit`, `SessionStart` and
     `Stop` [DOC].
   - **Skills.** `--disable-slash-commands` disables all skills and commands, including plugin and
     user skills [DOC].
   - **MCP.** `--strict-mcp-config` with no `--mcp-config` means zero MCP servers [DOC].
   - **Plugins.** `--plugin-dir` loads a plugin for one session only [CLI].
   - **Bare mode.** `--bare` skips hooks, plugin sync and CLAUDE.md auto-discovery, but reads no
     OAuth or keychain [CLI], so it cannot serve subscription accounts.
   - **Restricted mode.** `--restricted` ignores user, project and local settings files, but also
     removes the code-running tools unless `--tools` names them [CLI]. That makes it unsuitable as
     written for tasks that need a shell [I].
4. **Not documented [DOC]:**
   - which features stop loading when a source is left out of `--setting-sources`: hooks,
     enabled plugins, permissions, env, `CLAUDE.md`, `.claude/rules`;
   - whether that value can be empty;
   - any way to keep OAuth while skipping user-level `CLAUDE.md` discovery;
   - **how conflicting `PreToolUse` decisions from several hooks combine.** The documentation says
     matching hooks run in parallel, and that exit code 2 blocks unconditionally. Archeus's hook
     denies with a JSON `permissionDecision` and exit 0 (`archeus/harnesses/hook.py:41-43`, 145-146).
5. **What reaches those sources.** Third-party tools write into them when installed:
   - AgentMemory hooks;
   - OpenViking plugins;
   - Windows Harness `install-skill`;
   - Diagram Design packaging.

   A cloned repository can ship its own `.claude/settings.json` hooks and `.mcp.json`.

## The question

**Scope (part of the decision):** which sources does the rule cover?
- the account home (`user`);
- the project's committed `.claude/` (`project`);
- `.claude/settings.local.json` (`local`).

They differ: the project's `CLAUDE.md` is plausibly context the work *should* have, and a cloned
repository's hooks plausibly are not [I].

**For the sources in scope**, must a V1 execution exclude, record, or accept what they load, and
what may the user opt into?

**Sub-question (verification, not a choice):** can another source's `PreToolUse` hook widen what
Archeus's fail-closed hook denies? Not established. One documented way to make Archeus's deny
independent of the answer would be the exit-code-2 form. Recorded as an option, not adopted.

## Options

| Option | What it does | For | Against |
|---|---|---|---|
| A. Exclude | spawn with the narrowest `--setting-sources` that still authenticates, `--strict-mcp-config` (only Archeus-supplied servers), `--disable-slash-commands` | the execution's context is as close to Core's as the CLI allows; no third-party hook, skill or MCP server runs | managed settings still apply; whether user `CLAUDE.md` and the login survive each narrowing is undocumented and must be observed; the user's plugins, skills and MCP servers stop working inside executions, and a mission may need them |
| B. Record | at spawn, inventory what the sources in scope will load (hook commands, enabled plugins, skills, MCP server names, permission rules, `CLAUDE.md` hashes) into the execution's record; show it in Why | evidence-based; nothing breaks; the user can see and remove what they do not want | prevents nothing; the inventory reads files Archeus does not own (read-only, ADR-0046) and can only list what the documentation names |
| C. Accept | document that executions run with those sources | no work | context and code outside policy and outside the ADR-0047 basis, unrecorded |
| D. Exclude by default, opt in per account and source | A, plus a user-set allowlist (e.g. specific plugins via `--plugin-dir`, specific MCP servers via `--mcp-config`), recorded as in B | safe default with an explicit, recorded escape | most work; a new account-level field; still subject to A's undocumented points |

**Independent of A to D:** the deny form.
- **Keep the JSON deny:** today's behaviour; its precedence against other hooks is undocumented.
- **Deny with exit code 2:** documented as an unconditional block, and it changes how the reason
  reaches the agent.

Choosing between them is part of this decision, or of P20 if the user prefers.

## Decision (2026-10-03)

1. **Scope: all three settings sources** (`user`, `project`, `local`). Managed settings always
   apply and are outside the rule. They are recorded, never excluded.
2. **Option D, with option B's inventory always on.**
   - **Exclude by default.**
     - The spawn narrows `--setting-sources` as far as the login allows.
     - It passes `--strict-mcp-config`, with only Archeus-supplied or opted-in servers in
       `--mcp-config`.
     - It passes `--disable-slash-commands` unless a skill has been opted in.
   - **Opt in explicitly.** A user, through a command from a user device (the same pattern as
     ADR-0035's `data_class`), can opt specific sources, plugins (session-only, via
     `--plugin-dir`) or MCP servers back in. Each opt-in is versioned and recorded.
     - Where an opt-in is stored (account level or project level) and its exact command and
       UI are P20 design details, under that constraint.
   - **Always record.**
     - Every execution records an inventory of what its sources load: hook commands, enabled
       plugins, skills, MCP server names, permission rules, and `CLAUDE.md` hashes.
     - The inventory also records which items were excluded, which were opted in, and which
       could not be excluded.
     - The inventory is shown in Why. Its reads are read-only (ADR-0046).
   - **Fallback, stated rather than hidden.**
     - If PV-19's observed run shows that narrowing a source breaks the account's OAuth login,
       that source falls back to *recorded-only*, and the inventory and the UI say so.
     - Anything the CLI's flags cannot exclude (user `CLAUDE.md` discovery may be one; that is
       undocumented) is likewise recorded and shown as "loaded, not excludable".
3. **Deny form: exit code 2.**
   - Archeus's hook denies with exit code 2, which is documented as an unconditional block,
     with the reason on stderr.
   - Halt keeps its `continue: false` form.
   - P20 specifies and tests both forms, including how the reason reaches the agent and what
     happens on a hook crash and on a timeout. How a halt combines with exit code 2 is not
     documented, so it must be observed, not assumed.
4. **ADR-0047 needs no new clause.** An execution's pressure is measured from the usage the
   harness reports, which already counts every token the loaded sources add. The inventory is
   that context's *provenance*, recorded on the execution; it is not a second capacity measure.

## Consequences

- **P20** gains PV-10, the implementation of this rule, and PV-19, one observed execution per
  source that confirms what each flag excludes and that the login survives. PV-19 is gated by
  ADR-0021.
- **G6** gains tests for the exclusion, the inventory, the fallback and the exit-code-2 deny,
  and ADR-0051 lists them with the rest of the boundary.
- No V1 code changes until P20 is scheduled.
- Every undocumented point above stays a verification item until PV-19 runs. None of them is
  treated as fact.

## Revision (2026-10-03)

The reconciliation pass corrected three statements of the 2026-10-02 draft:
1. **The draft said** legacy hooks stand down only for a project with the cutover marker. **The
   P0.5 guard already silences them inside every execution** (Context item 2).
2. **The draft covered the account home only.** The CLI's settings sources include `project` and
   `local`, and the research question (XR-1) named project-level sources. The scope is now an
   explicit part of the question.
3. **Added** the documented facts on precedence, hook merging, managed settings, headless hooks
   and the skills and MCP flags; `--restricted` as a considered but unsuitable flag; and the deny
   form as an independent option.

No option was chosen in the revision. The decision followed the same day (see "Decision").
