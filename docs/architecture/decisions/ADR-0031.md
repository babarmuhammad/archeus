# ADR-0031: The model catalogue is dated current state, and discovery is not authorisation to route

**Status:** DECIDED (direction set by the user's directive of 2026-09-30, clauses K–M, R–S, X–Z; this record resolves O-1, O-2, O-7, O-8 and O-11 of the orchestration reconciliation) · **Date:** 2026-09-30 · Implementation: P21 (provenance fields), P22 (catalogue in Core), V1.x-O1 (aggregator rung) · Reconciliation: [ARCHEUS_V1_ORCHESTRATION_RECONCILIATION.md](../ARCHEUS_V1_ORCHESTRATION_RECONCILIATION.md) §8, §11, §12, §22

## Decision

1. **Facts about models are current state.** The `Model` and `ModelOffer` entities (domain-model
   §8.3, defined in P1 and unused until now) hold catalogue *facts* only: `provider`, `family`,
   exact `revision` (the provider snapshot; `null` when the source does not say), `alias_of`,
   `location` (remote | local), context window, max output, tool support, structured output,
   efforts, price where a source states it, availability, `deprecated_at`, `retired_at`, and per
   field the rung it came from, `source_ref` and `observed_at`. Provider terms stay in
   `ProviderTerms` (ADR-0021). No field is a capability score; performance claims are ADR-0032's.
2. **Ingestion path.** An adapter's own catalogue read (Anthropic `/v1/models` with the
   account's token, pi's catalogue, a provider proxy's `/v1/models`) → schema validation (a
   malformed catalogue is rejected whole; the last good one is kept) → provenance stamped → one
   writer transaction upserting rows and emitting events → routing status (clause 4). A fact past
   its TTL (24 h) is *stale*: still used, its age recorded in the decision; unknown is never read
   as zero; the bundled table is the floor.
3. **Per-field source precedence:** user override (explicit, dated) → the provider's own
   catalogue → provider documentation → an aggregator (models.dev), **opt-in and off by
   default** because it is a new outbound host (V1.x-O1) → the bundled floor table.
4. **Routing status** (a new state column on `Model`, entering `states.py` and
   `state-machines.md` with its implementation in P22):
   `CATALOGUED` (recorded; routable for no real work) → `EVALUATING` (routable only by an
   evaluation mission or an explicit user pin) → `APPROVED` (routable) ; `RETIRED` from any state
   when the provider withdraws it (and back to `CATALOGUED` if it reappears). Moves out of
   `CATALOGUED`/`EVALUATING` are made by the user, or by a **standing approval rule** the user
   created (e.g. "approve new revisions of family X"), which is recorded and cited by the move;
   `user_withdraws` returns a model to `CATALOGUED`. "Discovered" is the ingestion moment, not a
   state. **Routable = APPROVED (or EVALUATING for an evaluation subject) ∧ offer available ∧ not
   forbidden** — derived, never stored. Discovery never authorises routing real work.
5. **Exact ids, not moving aliases.** A routed offer names an exact model id wherever the
   catalogue knows one. A bare family alias that the harness resolves itself (Claude Code's
   `sonnet`, `opus`) is a moving target and is offered only when the harness accepts nothing
   more exact; the served model is then recorded (clause 6) and the offer is `route_kind: alias`.
6. **Provenance per execution** (P21): `Execution` records `model` (the requested id, harness
   vocabulary), `model_revision`, and `served_model` with its level — REQUESTED < ROUTED (a proxy
   says what it chose) < SERVED (the transcript's reported model) < BILLED (usage attributes it).
   The decision's `input_snapshot` gains the harness `installed_version` and the catalogue row
   versions it read. Rows are never deleted: a retired model keeps its row so old decisions
   stay readable.
7. **Opaque routers.** An offer whose upstream model is chosen by a proxy Archeus cannot see
   (OmniRoute `auto/*`) is `route_kind: opaque_router`. It is eligible for a subject that
   requires exact provenance (every task and review; ADR-0033 clause 2) only when its adapter
   *guarantees* recording the SERVED model; otherwise it is eliminated with that reason.
8. **Legacy `MODEL_PROFILES`** (`cap` 1–5, `swe`, `speed`, `best_for` in
   `claude_sessions/config.py`) is imported at P22, if at all, as REFERENCE knowledge with
   `source_kind: legacy` — historical material, excluded by construction from every evidence
   query and every routing step. Its numbers are never migrated as capability evidence.

## Why

The router cannot explain or replay a choice against facts it did not record; the same catalogue
the legacy app already reads ("the API owns facts; this repo owns editorial") is the right source.
Today's V1 offers include bare family aliases and the newest id per family
(`archeus/harnesses/calls.py:148-158`), so a provider release already changes which model does
the work with no decision recorded — the exact behaviour the directive forbids (clause X). Vicoa
keeps retired entries so history stays readable; OmniRoute's per-field precedence ladder is a
ready-made provenance model; fable-foreman flags NEW and STALE models before routing to them.

## Alternatives

Follow the newest model per family automatically (resource-router §2 as written — rejected by
clause X); approve per model with no standing rule (rejected: the user asked to decide *when* a
model becomes eligible, which a recorded standing rule is); a global allowlist in settings
(rejected: not versioned, not cited by decisions).

## Tradeoffs

A new model needs one explicit act (or a rule) before real work uses it. Exact ids can fail where
an alias would have resolved; the catalogue's retired-model handling (an Attention item for a
pinned retired id) covers that.

## Consequences

Amends resource-router §2 (offers come from the catalogue with routing status, not from
newest-per-family) and domain-model §8.3. At P22 the models the router offers today are imported
`APPROVED` with `source_kind: import`, so the migration changes no current routing silently. New
events: `catalog.model_released` (registered, first emitted in P22), `catalog.model_changed`,
`catalog.model_retired`, and `model.state_changed` for routing-status moves.
