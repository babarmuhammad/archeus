# ADR-0006: The brain is Core-side structured-output calls; control verbs are deterministic

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Archeus reasons through headless structured-output model calls made by Core (routed like any work, with a reserved allocation), whose outputs are validated against JSON schemas and then applied as commands by Core. Control verbs (pause, resume, stop, approve, reject, reprioritise, status, why) are parsed by a deterministic grammar and never need a model. Exposing Archeus as an MCP server to a harness is deferred. Brain calls belong to the **tool-less structured call** class (rearchitecture plan §31.4): they run only through the `llmcall` runner, require the ADR-0021 gate, and until the router exists (P10) take their account from legacy `rotate.elect()` + `quota.reason()`.

## Why

An MCP-server brain would depend on the whole execution stack, pay a cold harness spawn per message, compete with task quota, write transcripts into the user's project lists, and hold tools broad enough to approve its own proposals. Structured calls reuse a proven pattern in the repo and keep authority in Core. Deterministic control keeps Archeus stoppable when every account is exhausted.

## Alternatives

Brain as an MCP-connected harness session; brain with direct tool access.

## Tradeoffs

Less agentic freedom for the brain (it proposes; Core applies).

## Consequences

Schemas live in `core/brain/schemas/`; the brain principal has the `propose` scope only.
