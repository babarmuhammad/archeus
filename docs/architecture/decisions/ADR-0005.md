# ADR-0005: Resource router: priority, ceiling allocation, affinity, persisted decisions

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

A deterministic router selects (harness, account, model) through eliminating steps (capability, enforcement, policy, restrictions, health, allocation) and an ordering (affinity, preferences, priority, tier fit, health, cost, latency). Allocation is a ceiling on the provider-reported window utilisation, with reserve, brain reserve, stale-usage penalty and ledger budgets when no window is readable. Every decision persists its input snapshot and rejected candidates.

## Why

Priority and allocation must be independent (spec §15). Providers report utilisation that includes the user's own use, so a share-of-pie model is not implementable; a ceiling is. Affinity preserves prompt caches and avoids pointless hand-offs. Persisted snapshots make "why account B?" answerable and decisions replayable.

## Alternatives

Sticky threshold rotation (today); weighted random load balancing; a model deciding the route.

## Tradeoffs

Ceilings are conservative and depend on usage freshness.

## Consequences

Router is pure given a snapshot; tested with property tests and a fake usage feed.

## Amended (2026-09-30, ADR-0031, ADR-0033, ADR-0035)

The decision stands unchanged in kind: a deterministic, replayable router over eliminating steps
and an ordering. ADR-0031 makes the model step read the dated catalogue and admit only models in
routing status APPROVED (EVALUATING for an evaluation subject), with exact ids where known.
ADR-0035 adds the data-class provider rule to the restriction step. ADR-0033 adds a `provenance`
step, an `evidence` step that eliminates only under a user's `evidence_exclude` rule, one discrete
`evidence_fit` ordering key after priority and before tier fit only under a user's
`evidence_order` rule, a frozen `capability_snapshot` in every decision, and bounded escalation as
the named rule `escalate_on_repeated_failure`. No weighted score is introduced.
