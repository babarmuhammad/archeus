# ADR-0028: Colour separation, depth and transparency tokens

**Status:** DECIDED (user directive and approval, 2026-09-30) · **Date:** 2026-09-30 · Implementation owner:
P19.5 (defects may close with P18, ADR-0030) · Rulebook §23, §24, §38

## Decision

1. **Focus is not attention.** `focus` moves from `#FFD166` to thread ink (`#F4F1EA` dark,
   `#11151C` light), 2 px with offset. Measured: `#FFD166` vs attention `#F2B544` is ΔE 12.3
   (CIE76) — a focused graph node read as "needs you". Gate: focus ≥ ΔE 30 from every state colour.
2. **Red is reserved** for a problem the user must resolve (blocked, failed needing action).
   Informational and retrying states use neutral text: the narrow-graph note (`GraphView.tsx:42`)
   and `Loadable` failures that are still retrying stop using `.unavailable` → `state-blocked`.
3. **Depth and transparency are fixed tokens**, never ad-hoc values: `alpha-recede .40`,
   `alpha-tier1 .64`, `alpha-tier2 .36`, `hull .06 / hull-focus .10`, `halo-outer .35 /
   halo-inner .70`, elevation 0/1/2 (DS §6), z-layers canvas 0 / chrome 10 / drawer 20 / toast 30 /
   modal 40 / tooltip 50. Reduced transparency and forced colours make them opaque.
4. **Overlays are opaque** (resolves DS "92–96 %" vs P16 as built). **No** `backdrop-filter`,
   blur, blend modes, bloom, fog, bokeh or surface gradients; the only gradient is the thread's
   travelling highlight.
5. Semantic tokens only — no one-off colours in components.

## Why

DS §3.2 ("red = a problem needs resolving"); the measured collision; the Qt readback lesson and
R6's "glass only on a floating functional layer"; PROMPT 1567-1592 (transparency and depth only
when they support hierarchy).

## Consequences

Token table in the rulebook §38; contrast/ΔE gate extended; computed-style gate for focus.
