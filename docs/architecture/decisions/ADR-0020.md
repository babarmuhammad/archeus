# ADR-0020: Automation as event/schedule/condition/state triggers creating missions under policy

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Automations are persistent rules whose triggers create missions from templates; they run through the normal mission loop, are policy-checked, carry cause chains with a depth cap that escalates, are rate-limited, suspended on repeated escalation, and simulated before enabling. Scheduling is claim-and-advance in Core.

## Why

Spec §21: automation is a persistent rule, not a cron job. Reusing the mission loop gives automations verification, audit and approvals for free.

## Alternatives

OS schedulers (today's loops); a separate workflow engine.

## Tradeoffs

Core must be running for schedules (autostart offered).

## Consequences

Legacy loops and auto-memory become automations at cutover.
