# ADR-0054: The mission lifecycle spine: six stations, drawn from Core's mission state and `held_from`, never guessed

**Status:** PROPOSED. The six stations are the owner's decision (V2 real build, Q11, 2026-10-25); the rest awaits the aimed Codex review. · **Date:** 2026-10-25 · Implementation: V2-U1 slices c and d, on the `v2/real` branch, which does not merge to the release line before the P26 decision · Reads ADR-0017, ADR-0024, ADR-0026, ADR-0044 · Source proposal: [ARCHEUS_V2_UI_RESEARCH.md](../../design/ARCHEUS_V2_UI_RESEARCH.md) §6.3 P-1 (which asked for seven stations; see §1)

## Context

A mission shows its state as a badge and a status line. Nothing on any surface shows where the mission is in its life (research A13). The V2 prototype draws six stations, Understand, Plan, Approve, Run, Verify, Review, but only on one frame, from a fixture integer, at hard-coded x positions. The real app needs one primitive that a list row, a card and the inspector header all draw, fed by Core's own fields.

Facts this decision rests on, checked against the tree at 539b29a:

- `Mission.state` has 17 values (`archeus/core/domain/states.py`, machine `mission`). It is on every row of `GET /v1/missions`.
- `Mission.held_from` is a field of the entity (`entities.py`), set on the way into BLOCKED or PAUSED and cleared on the way out of RESUMED (`commands._record_hold`). `queries.view()` is `entity.to_dict()`, so `held_from` is on every list row and on the detail read. `generated.ts` types it only through the index signature of `Mission`, so the client must narrow it.
- A hold is only ever entered from a station state: BLOCKED from UNDERSTANDING, REASONING, EXECUTING, REPLANNING or VERIFYING; PAUSED from EXECUTING.
- Leaving BLOCKED or PAUSED by `cancel` does not clear `held_from`; leaving PLANNING, APPROVAL_REQUIRED, CREATED or FAILED by `cancel` never set one. So after CANCELLED the field is sometimes there and sometimes not.
- Core's own rule for a hold with no record is "refused, never guessed" (state-machines.md, `resume`).
- Each state change is a `mission.state_changed` event with `at` and `payload.from/to`. The timeline read is capped (50 per page, 100 at most) and event retention may prune old events.
- The Ideas stepper (`Work.tsx IdeaPath`, `state/ideas.ts`) already draws "where an idea is" as an `ol` with `aria-current='step'`.

## Decision

1. **Six stations, in this order.** Understanding, Planning, Approval, Executing, Verifying, Reviewing. There is no seventh "Done" station: a completed mission shows all six passed and the Done colour. This replaces the seven of research P-1 (owner, Q11). Each station is named by a Core state word. `tokens/spine.json` gives every station a `label` and an `anchor` state, and `tools/gen_ui.py` refuses a label that does not occur, case-insensitively, in Core's label for its anchor state (`presentation.json` labels, so "Approval" in "Waiting for approval", "Executing" in "Executing"). A word Core does not use cannot become a station name.

2. **The state to position mapping is a generated table, not code.** `tokens/spine.json` maps every mission state to a position, and `gen_ui.py` refuses a mission state with no entry, the same way `problems()` refuses a state with no presentation class. The shipped mapping:

   | Mission state | Station reached | Mark on it |
   |---|---|---|
   | CREATED | none | none; every station ahead; text "not started" |
   | UNDERSTANDING, CONTEXT_GATHERING, REASONING | 1 Understanding | current |
   | PLANNING, REPLANNING | 2 Planning | current (a replan shows stations 3 to 6 ahead again) |
   | APPROVAL_REQUIRED | 3 Approval | current, needs-you figure |
   | APPROVED | 3 Approval | passed; Executing ahead; text "not started" |
   | EXECUTING | 4 Executing | current |
   | VERIFYING | 5 Verifying | current |
   | REVIEWING | 6 Reviewing | current |
   | COMPLETED | all six | all passed, drawn in the Done colour |
   | FAILED | 4 Executing | failed (FAILED is reachable only from EXECUTING) |
   | BLOCKED, PAUSED | the station of `held_from` | held (blocked or paused figure) |
   | RESUMED | the station of `held_from` | current (a transient state inside one transaction) |
   | CANCELLED | none | none; text "Cancelled" |

   The generator also checks three closure rules: every edge in `states.TABLE` into BLOCKED or PAUSED comes from a state that has a station (so a valid `held_from` always resolves); every predecessor of FAILED maps to the station FAILED sits on; and only COMPLETED yields an all-passed spine. A new mission state or a new hold edge fails the build until the table says where it goes.

3. **The never-guess rule.** The spine reads exactly two fields, `state` and `held_from`.
   - BLOCKED or PAUSED with a missing `held_from`, or one that is not a station state, draws no position: every station is "unknown" (dotted) and the text says "Blocked, position unknown." Nothing else is used to fill the gap: not the plan version, not the tasks, not a pending approval, not the timeline, not another read.
   - CANCELLED never uses `held_from`, even when one is left over, because it is present only for some paths into CANCELLED and using it would make the figure depend on how the mission was cancelled.
   - A state the client does not know (an older client on a newer Core) draws the state's own word and no stations, never a guessed neighbour.
   - Passed stations are drawn in ink, not in the Done colour. Only COMPLETED turns the spine Done, which keeps the existing rule that only a completed mission is done (`test_only_a_completed_mission_is_done_and_ended_ok_is_not_success`).

4. **Marks and colour follow the presentation class, never a new colour.** The mark on the current station is the glyph and role that `present('mission', state)` already gives (planning ◌, needs you ◆, approved ◇, active ● for Executing, Verifying and Reviewing, blocked ■, paused ‖, failed ✕). Passed is a solid disc with a check, not reached is a hollow ring, unknown is a dotted ring. Segments between marks follow the line-style vocabulary of the visual language document: solid up to the current station, dashed after it, dotted when the position is unknown. Colour is never the only carrier: every mark differs in shape and every position has words.

5. **Three sizes, each drawn for its size, one component.** `src/components/Spine.tsx` takes `state`, `held_from` and a `size`.
   - **row:** six marks of 8 px, 64 px wide, 12 px high, no labels. In `MissionRow`, which covers Work (groups, pinned) and Now (Happening now, Upcoming) with one change. The state badge and the status line stay; the spine never replaces the glyph and word.
   - **card:** six marks of 10 px joined by segments, about 120 px wide, with the current station's label in caption type.
   - **inspector header:** six marks of 16 px with all six labels in caption type, as an `ol` with `aria-current='step'` (the same semantics as `IdeaPath`), and, where the timeline read covers it, the time at each station. A time that the read cannot show (events pruned, page partial) is omitted, not estimated. Below a 480 px container width the labelled form becomes a vertical list; the choice is a container query, never a width media query (`a_width_media_query_moves_only_the_chrome`).
   - The spine is never interactive and is not a hit target at any size.
   - It is static: no animation, no transition. A change of station redraws; the existing `state-change` 160 ms cross-fade on the badge is the only motion, and it is not the spine's (ADR-0055).
   - It draws no left-edge rule (the thread rule owns a row's left edge, ADR-0026).

6. **The text equivalent is real text and is generated.** The figure is `aria-hidden`. Next to it the component renders a sentence as text content (visually hidden at row and card size, visible at inspector size), built only from Core's state word and the table, never from free text:

   | Situation | Sentence |
   |---|---|
   | station current | `{state word}, step {n} of 6.` e.g. "Executing, step 4 of 6." |
   | APPROVED | `{state word}, 3 of 6 steps passed.` |
   | held or failed | `{state word} at step {n} of 6 ({station label}).` e.g. "Blocked at step 4 of 6 (Executing)." |
   | hold with no valid `held_from` | `{state word}, position unknown.` |
   | CREATED | `{state word}, not started.` |
   | CANCELLED | `Cancelled.` |
   | COMPLETED | `{state word}, all 6 steps passed.` |

   `{state word}` is Core's label from `presentation.json` verbatim. A test builds the sentence for every state, and for every BLOCKED and PAUSED state with every valid and one invalid `held_from`.

7. **The terminal form.** The TUI draws the six marks as one cluster followed by the station word, from the same generated table (`_tables.py`) through `present.py`'s `spine()`, with the shared cases in `parity.json`:

   | Case | Unicode | ASCII fallback |
   |---|---|---|
   | Executing | `✓✓✓●○○ Executing` | `+++*oo Executing` |
   | Blocked at Executing | `✓✓✓■○○ Blocked` | `+++#oo Blocked` |
   | Paused at Executing | `✓✓✓‖○○ Paused` | `+++=oo Paused` |
   | Waiting for approval | `✓✓◆○○○ Approval` | `++!ooo Approval` |
   | Position unknown | `?????? Blocked` | `?????? Blocked` |
   | Completed | `✓✓✓✓✓✓ Done` | `++++++ Done` |
   | CREATED | `○○○○○○ Created` | `oooooo Created` |
   | CANCELLED | `–––––– Cancelled` | `------ Cancelled` |

   The ASCII set is the one `presentation.json` already holds for each class (`+` done, `*` active, `!` needs you, `#` blocked, `=` paused, `x` failed, `o` proposed or not reached, `-` inactive, `~` planning, `^` approved). The TUI has no motion.

8. **The offline view.** `OfflineNow` draws the row form from the kept missions, which keep their full rows (`keptData` filters only ended missions), so `held_from` is there. It stays read-only text plus the figure.

9. **Other surfaces.** Attention items carry `mission_id` but not the mission's state, so a spine on an Attention row needs the missions list, which Now and Work already read; it must be a join on that read, not a new request per row. The graph's semantic-zoom spine tier is V2-U5, not this ADR.

## Why

The spine answers "where is this?" on every surface without reading, and it replaces three ad hoc forms (status line, "0 of 1 tasks done", Upcoming against Happening). Reading only `state` and `held_from` keeps it honest: both are Core's records, both are on the list row, and no client rule decides what a mission means (ADR-0017's one-colour-one-meaning discipline, the presentation tables' "a class says how a state looks, never what it means").

Six stations instead of seven because the owner reviewed the prototype's six, and because a Done station would be a seventh figure that is only ever reached by finishing the sixth. COMPLETED already has its own colour and word.

## Alternatives

Seven stations with Done (the research proposal): rejected by the owner. Position by event history for BLOCKED and PAUSED: rejected, retention may prune events and Core's own rule is that history is not the answer. Guessing a station from the plan or tasks when `held_from` is absent: rejected, it is the exact behaviour Core refuses. A spine drawn only in colour or only as an icon: rejected, accessibility and ADR-0017. Hand-written mapping in the client and again in the TUI: rejected, one generated table is how presentation classes stay equal in both.

## Tradeoffs

A new generated table and its refusals to maintain; a state added to `states.py` now fails the build until it has a station. `held_from` is untyped in `generated.ts`, so the client narrows it with a runtime check; typing it needs a Core schema change, which this ADR does not ask for. Row spines show the station only: task counts ("2 of 5 done") are not on the list row.

## Consequences

New: `tokens/spine.json`; generated `src/state/spineTable.ts` and the `SPINE` table in `archeus/cli/tui/_tables.py`; hand-written `src/state/spine.ts` (`spineOf(state, heldFrom)`), `src/components/Spine.tsx`, `present.py spine()`; `test/spine.test.ts`; parity cases; a design gate that every mission state is mapped. Amends nothing in V1 behaviour. Gates that stay as they are and bind this work: `the_left_edge_of_a_row_belongs_to_the_thread`, `only_a_completed_mission_is_done`, `components_render_text_never_markup`, `a_width_media_query_moves_only_the_chrome`, the idle invariant (the spine adds no animation), and `the_generated_ui_files_are_current`.
