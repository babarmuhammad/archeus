# ADR-0017: Design language: fixed state colours, one signature element, skins/worlds not carried

**Status:** DECIDED · **Date:** 2026-09-23 · *V2 (branch `v2/real`, not merged before P26): the colour values are replaced by the V2 palette in [ARCHEUS_V2_VISUAL_LANGUAGE.md](../ARCHEUS_V2_VISUAL_LANGUAGE.md) §3; the rule (one colour, one meaning, in every theme) is unchanged.*

## Decision

State colours and glyphs are fixed across all themes; accent is used for primary actions and the thread only; themes are Dark, Light, High Contrast; legacy palettes survive as accent choices; skins and worlds are not carried into the V1 client.

## Why

One colour must mean one thing for an agentic system the user must trust at a glance; 39 palettes × 8 skins cannot hold that.

## Alternatives

Carry skins/worlds; per-theme state colours.

## Tradeoffs

Loses a loved customisation surface (open question: a Classic appearance).

## Consequences

Tokens generated from one table; contrast gate over themes.

## Amended (2026-09-30, ADR-0026, ADR-0028)

"Legacy palettes survive as accent choices" and "accent is used for primary actions and the
thread" are superseded: after design review B.1 there is no hue accent; legacy palettes survive
**only as thread tints** (ADR-0026), which never carry meaning. Focus moves to thread ink so it
cannot be read as attention (ADR-0028). The Classic appearance question stays recorded as decided
by P16 D12; whether that was the user's decision is still to be recorded (rulebook §31 Q-C1).
