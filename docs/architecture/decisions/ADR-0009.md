# ADR-0009: Realtime by SSE with ids-only events and client re-query

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Clients subscribe to one SSE stream (fetch-streamed so the token is a header), receive event ids/types/subjects and re-query what they display. Replay uses Last-Event-ID; retention expiry returns 410 and a snapshot resync. Streams use a separate bounded pool; browsers share one stream across tabs through a leader tab.

## Why

Stdlib has no WebSocket. Ids-only events make missed or reordered events harmless (Vicoa's wake-and-requery). A separate pool prevents long-lived streams from starving commands under HTTP/1.1.

## Alternatives

WebSockets; polling (today); state-carrying events.

## Tradeoffs

One extra query per relevant event (cheap on local SQLite).

## Consequences

Every screen must be re-queryable by subject; the API is resource-shaped.
