# ADR-0019: Data ownership during the strangler period

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

Before cutover the legacy app owns writes to memory graphs, CLAUDE.md managed blocks, rules files, hook settings and account settings; V1 imports read-only snapshots and installs hooks only per execution. After cutover V1 owns them. V1 executions are tagged so legacy lists and auto-memory skip them.

## Why

Two writers of the same file is the failure this codebase has hit repeatedly (import-time bindings, duplicated tables).

## Alternatives

Shared writes with locking; immediate cutover.

## Tradeoffs

V1 knowledge lags legacy memory until cutover.

## Consequences

Ownership table in migration-plan §5; export back to legacy formats for 90 days after cutover.
