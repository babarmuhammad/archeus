# ADR-0016: Spatial visualization: 2D fine-line, semantics only; 3D later

**Status:** DECIDED · **Date:** 2026-09-23

## Decision

The World graph is a 2D fine-line view in which every visual variable maps to a domain fact (cluster = project, node shape = kind, line style = confidence, energy = live execution). It has a list equivalent. A 3D mode may reuse the current flat graph-scene lineage after V1. The ambient background stage is not carried into the V1 client.

## Why

Principle 21: visualization must represent meaningful relationships. 2D is more legible, accessible and cheaper; the repo already learned that heavy 3D caused flicker and overstimulation.

## Alternatives

3D world as home; decorative background stage.

## Tradeoffs

Less spectacle in V1.

## Consequences

Encoding table is tested against the renderer.

## As built (P18, 2026-09-29)

The encoding table is `clients/app/src/graph/encoding.ts`. Two readings changed from the
research's §26 list, recorded as p18-design-gate V1 and V7: a **ring is a session** (P16 §20.10;
V1 has no person table), and a **diamond is a DECISION-type knowledge item** (the Decision
entity has no table; its knowledge item is its record). Cluster = project holds; at the world
level a project is drawn collapsed with its counts (V3).

## Amended (2026-09-30, ADR-0024, ADR-0025, ADR-0027)

The ambient background stage stays not carried; its principle — "one surface behind, driven by
state" (research §7) — moves to the mark's orbit and the operations strip (ADR-0027). Energy is no
longer only a pulse: a static activity halo and an event-driven travelling marker are added
(ADR-0024; the P18 A8 amendment is ADR-0030, PROPOSED). Edge treatment by recorded confidence tier,
the legend, the impact view, hull, depth tiers and the static project cage are ADR-0025. "Lists
remain the primary UI" is refined: lists are the primary *control* surface; a bounded live map on
Now is the primary *overview* (ADR-0027).
