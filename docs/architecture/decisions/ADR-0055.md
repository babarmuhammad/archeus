# ADR-0055: Motion registry v2: duration classes, written "does not move" rules, and one liveness exception, the core breath (amends ADR-0024)

**Status:** PROPOSED. The breath exception is the owner's decision (V2 real build, Q5 "Keep breath, amend the gates", 2026-10-25); the rest awaits the aimed Codex review. · **Date:** 2026-10-25 · Implementation: V2-U1 slice b, on the `v2/real` branch, which does not merge to the release line before the P26 decision · Amends ADR-0024 §2, §3 and §4 (nothing else in it) · Reads ADR-0026, ADR-0029, ADR-0043, ADR-0044 · Source proposal: [ARCHEUS_V2_UI_RESEARCH.md](../../design/ARCHEUS_V2_UI_RESEARCH.md) §7.4

## Context

ADR-0024 makes the registry (`clients/app/tokens/motion.json`) the only place an animation may be declared, forbids loops, and requires zero animations at idle. The V2 prototype breathes its core: one layer scales 1 to 1.018 and back over 6000 ms while a confirmed execution is running (`app.js` ~2533, a WAAPI animation with `iterations: Infinity`). Its own reduced motion and Quiet form is a static running mark and every fact at once. The owner wants the real app to keep the breath and has approved amending the V1 design gates for that one beat and nothing else.

What V1 enforces today, all checked in the tree (`tests/v1/design/test_design_gates.py`, `tools/gen_ui.py`, `clients/app/test/motion.test.ts`, `tests/v1/e2e/test_spa_motion.py`, `tools/mutate_p19_5.py`):

- no `infinite`, no `steps(`, every `animation` shorthand ends in `1`, no `animation-iteration-count` (`..._and_nothing_loops`);
- every `.animate(` names a built loop motion (`every_loop_animation_is_a_registered_built_motion`);
- `motion_problems` refuses a non-static entry whose `idle` is not `never` or whose `driven_by` is `state`;
- the TS registry test requires the same;
- the e2e idle test asserts zero running animations and no unbounded animation on every destination (its fixture mission is COMPLETED);
- the mutation suite kills a perpetual CSS animation on an idle page (N23) and infinite `thread-draw` and `orbit-turn` mutants.

## Decision

1. **Duration classes.** The registry's durations get names. The values stay the approved tokens (`tokens.json motion`); a class is a name for them, not new numbers. Every registry entry carries a `class`, and `gen_ui.py` refuses an entry whose `max_ms` is not one of its class's values.

   | Class | Token and value | Easing | Entries today |
   |---|---|---|---|
   | `instant` | none, 0 ms | none | selection, focus, hover on frequent controls, everything under reduced motion |
   | `quick` | `state`, `toast`: 160 | `--ease` | state-change, dialog-open, pointer-affordance, toast, activity-chip |
   | `standard` | `pulse`: 240 | linear for opacity steps, else `--ease` | execution-pulse, row-pulse, attention-arrival, camera-settle |
   | `layer` | `row` 200, `inspector` 220, `sheet` 280 | `--ease` | thread-rule-fade, inspector-open, sheet-open |
   | `travel` | `travel`: 600 | linear or ease-in-out | travelling-marker, thread-travel |
   | `orbit` | `orbit`: 900 | ease-in-out | presence-orbit |
   | `breath` | `breath`: 6000 | ease-in-out | core-breath, and only it |

   A new beat uses an existing class; a new duration value, or a second `breath` entry, is an amendment to this ADR. Effects (opacity, colour) never overshoot. Everything ADR-0024 §4 says about rules for every animation stands (transform and opacity only, capped, interruptible, a pure function of state and presentation time, no replay) except the three clauses §4 below changes.

2. **Every registry entry names a `moment`, and the moments that do not move are written down.** `motion.json` gains a closed `moments` vocabulary and a `still` list. An entry's `moment` must be a moving moment; `gen_ui.py` refuses an entry whose moment is in `still`. The still moments are:

   | Moment | Rule | Text or static equivalent |
   |---|---|---|
   | arriving (a row or card appears because Core created it) | rows appear at once; the thread rule marks the change | "changed since you looked" |
   | disappearing (an object left the read) | rows leave at once | none needed |
   | thinking, planning | a static figure and specific text; no spinner, no loop | "Planning: ..." |
   | failing | the 160 ms state cross-fade only; no shake, no pulse, no toast | the reason, inline |
   | quiet, stale liveness | text with its age; no motion | "no output for 12 min" |
   | reconnecting | banner text and the hollow presence node | the banner, announced |
   | station change on the spine (ADR-0054) | the spine redraws; it has no entry | the spine's sentence |
   | a count or a figure changing without a Core event (filter, sort, tab, route switch) | instant | none needed |
   | scrolling, hover on a row, selection, focus | instant | none needed |
   | a loading skeleton | static, as today | none needed |
   | the graph layout settling | static, as today | none needed |

   View Transitions between routes stay deferred to V2-U6 and would need registry entries of their own.

3. **Liveness has no motion, with one exception.** Silence, staleness and "is it still working" are shown by text with its age and by the existing static halo (`activity-halo`, `idle: static`), never by a loop. The single exception is the **core breath** (`core-breath`), approved by the owner for exactly this beat:

   - **What moves.** One DOM element, the core mark of Now, a layer separate from the graph canvas: `transform: scale(1)` to `scale(1.018)` to `scale(1)`, 6000 ms per cycle (3000 out, 3000 back, `ease-in-out`), centre fixed. No colour, opacity, blur, glow or filter change. Nothing else in the application loops.
   - **How it runs.** A CSS keyframe `core-breath` on `[data-core='breath']` with `animation-iteration-count: infinite`, compositor only. It is not a WAAPI call and not a `requestAnimationFrame` use, so `graph/loop.ts` stays the only frame caller and the `.animate(` gates are untouched. (The prototype used WAAPI; the real app does not.)
   - **When it runs.** Only while all of these hold: the Core read behind the live-work halo (ADR-0043, `LiveItem` in `generated.ts`) shows at least one execution whose presentation class is active; that read's freshness is `current` (connection `live` or `resynced`); the document is visible; motion mode is `full`. Any other connection state, a failed re-read, a hidden tab or reduced motion stops it at once. It starts on a read, never on a client timer, and it clears when a read shows no live execution (hysteresis as ADR-0024 §5 for halos). A re-read, resync or reconnect redraws state and never replays or restarts a breath.
   - **The static twin.** Reduced motion (`html[data-motion='reduced']`, the existing `Reduced` preference, and `prefers-reduced-motion`) and Quiet set scale 1 and show a small static running mark with text ("N running", the same count as the state sentence) while the same running fact holds. The mark is hidden when the fact does not hold and never shown in full motion, where the breath is the cue. In the real app Quiet is the existing `Reduced` preference; a separate third Quiet setting would be a new owner decision.
   - **Registry entry.** `idle: live-only` (new), `driven_by: state` (a state-following loop; allowed only for this entry), `runs_on: css`, `css: ['core-breath']`, `max_ms: 6000` (class `breath`, token `breath`), `cap: 1` per surface, `surfaces: ['Now']`, `replay: false`, a new field `loop: true`. `reduced` and `equivalent` as above.
   - **Idle invariant, as amended.** With no live execution, no arriving change and no user input the client schedules zero animation frames and runs zero animations, as before. While a fresh read shows a live execution, exactly one animation may run: `core-breath`, on one element. Anything else running is a failure.
   - **What the breath is not.** It is not evidence of output (the pulse and the marker are), not a heartbeat, not a spinner and not an activity indicator for a single execution; it says only "Core has live work", the same fact as the halo and the sentence. It never starts for an automation tick, a demo, a fixture or a queued mission (ADR-0024 §7, no fake activity).

4. **Which prototype beats become registry entries.** The prototype's creation beats (reply 0, appear 160, relation 240 from 160, label 180 from 400, accent gone by 800) belong to the chat-to-map choreography of V2-U7 and the map of V2-U5, not to U1.
   - **Accent gone by 800 ms** (an event outline, 1/2/1 px over 240 ms, 2 s object cooldown): this is the existing `execution-pulse` (240 ms, at most 1 per 2 s per object). No new entry.
   - **Appear 160 and relation 240:** one new entry, `node-arrive`, status `approved` (not built until U5 or U7 binds it), class `quick` (160) for the node and the label as one opacity step, with the relation at class `standard` (240) in the same loop motion, run on the graph loop as `renderAt(t)`. The 400 ms label stagger and the 180 ms value are dropped: no new duration. It is triggered by a Core read showing a record the user's own message made, cap 1 batch per surface, `idle: never`, `replay: false`.
   - **Glyph approach of 24 px over 360 ms, event outline cooldown parking, scroll parking:** not ported. Parking on hidden is kept (§3); parking on blur and on scroll is not adopted because the breath and the others are compositor animations, not scene redraws; revisit with a measurement.
   - **Core breath:** the one entry of §3, status `approved` in U1-b and `built` when U1-h binds the element.

## Why

The prototype's own reduced and Quiet form already is the V1 idle form; the owner decided that one beat of liveness is worth a narrow exception. Keeping it a CSS keyframe on one element, driven by the same read that drives the halo and parked by the same conditions as the rest of the registry, means the exception costs one registry entry, one named allowance in each gate, and nothing else. Naming the classes and the still moments turns what V1 already does implicitly into rules a reviewer can check.

## Alternatives

A static running mark only (the plan's recommendation): declined by the owner. A WAAPI infinite animation as in the prototype: rejected, it would need the `.animate(` gate and the loop-only rule amended and would bypass the registry's CSS binding. Breathing the whole map or the shell mark: rejected, "only the core layer". A breath that runs whenever Core is connected: rejected, it would be a fake liveness signal (ADR-0024 §7).

## Tradeoffs

One registry entry and four gates carry a deliberate exception, which every later review has to keep narrow. A continuously running compositor animation costs some battery on a laptop with live work; it stops with live work, a hidden tab and reduced motion, and it needs a measured check on the iGPU target before U1-h is accepted (unmeasured here).

## Consequences

Gates and tests that must be amended in slice U1-b, each narrowly, and mutation-verified:

1. `tests/v1/design/test_design_gates.py::test_transitions_move_only_transform_and_opacity_and_nothing_loops`: strip the one rule `[data-core='breath']` that declares `animation: core-breath var(--dur-breath) ease-in-out infinite` and assert that exactly one such rule exists, in `app.css`, naming `core-breath`; every other `infinite`, `steps(`, or `animation-iteration-count` still fails.
2. `tools/gen_ui.py` (`MOTION_FIELDS`, `_ONE_OF`, `motion_problems`): add `class`, `moment`, `loop`; allow `idle: live-only` and `driven_by: state` on a non-static entry only when `loop` is true; refuse a second `loop` entry, a `loop` entry that is not `core-breath`, one that is not `runs_on: css`, one with a `cap` other than 1, one with `replay` not false; refuse an entry whose `max_ms` is not in its class; refuse an entry whose `moment` is in `still`. `tokens.json motion` gains `breath: 6000` (emitted as `--dur-breath`).
3. `clients/app/test/motion.test.ts` "every registered motion carries the metadata": the `idle === 'never'` and `driven_by !== 'state'` checks exempt exactly an entry with `loop === true`; a new test pins that exactly one entry has `loop`, that it is `core-breath`, 6000 ms, scale amplitude at most 1.018 in the keyframe, `cap` 1.
4. `test_the_motion_registry_holds_the_approved_budgets`: add the `core-breath` budgets and the class table.
5. `tests/v1/e2e/test_spa_motion.py` and every e2e that asserts no running animation (`test_spa_arrival`, `test_spa_halo`, `test_spa_marker`, `test_spa_rows`, `test_spa_strip`, `test_spa_thread`, `test_spa_toast`, `test_spa_cage` use `running_animations` or `getAnimations()`): none changes while its fixture has no live execution on a page that mounts the core mark. Any that does gets a helper that filters the animation named `core-breath` and asserts at most one of it. New e2e: with a live execution fixture, exactly one running animation named `core-breath`, infinite; with `data-motion='reduced'` none and the static mark shown; after a read showing no live work, none; with the connection lost, none; hidden tab, none.
6. `tools/mutate_p19_5.py` mutants N23, the infinite `thread-draw` and the infinite `orbit-turn` must still be killed (the exception is keyed to `core-breath`, not to `infinite`); new mutants: a second infinite animation, `core-breath` with `iterations` on another selector, breath without the live read, breath under reduced motion, breath animating `opacity`.

Gates that stay unchanged and bind this work: `keyframes_animate_only_transform_and_opacity`, `every_keyframe_and_transition_is_a_registered_motion` (it passes once the entry is built), `every_loop_animation_is_a_registered_built_motion`, `the_graph_loop_is_the_only_animation_frame_caller`, `no_readback_effects`, `reduced_motion_contrast_and_forced_colours_are_honoured`, the idle e2e on its COMPLETED fixture. ADR-0024 gets one header line pointing here; its text is not rewritten.
