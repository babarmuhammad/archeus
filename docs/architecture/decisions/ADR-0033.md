# ADR-0033: Evidence advises routing; it orders or excludes only under an explicit rule; the router stays ADR-0005

**Status:** DECIDED (direction set by the user's directive of 2026-09-30, clauses C–J, W–X; this record resolves O-4, O-7, O-14 and O-16 of the orchestration reconciliation) · **Date:** 2026-09-30 · Implementation: P21 (snapshot fields), V1.x-O2 (evidence steps and rules) · Extends ADR-0005 · Reconciliation: [ARCHEUS_V1_ORCHESTRATION_RECONCILIATION.md](../ARCHEUS_V1_ORCHESTRATION_RECONCILIATION.md) §13, §18, §19

## Decision

1. **The router remains a pure, deterministic function of (requirements, snapshot)**, replayable
   from its own record. "Most powerful model" is not an algorithm, a fallback or a tie-break.
2. **Requirements gain** `task_family` (ADR-0032) and `exact_provenance` (true for every task and
   review; false only for own calls whose purpose tolerates it). **Elimination order:** installed
   → headless → capability → model (routing status, ADR-0031) → enforcement → provider terms →
   restriction (incl. data class, ADR-0035) → **provenance** (an offer that cannot guarantee a
   SERVED record fails an `exact_provenance` requirement) → health → allocation → **evidence**
   (only under an `exclude` rule) → election. Policy and resource constraints always precede any
   evidence step.
3. **Three evidence behaviours, the first by default:**
   - **annotate** (default everywhere): each candidate's row carries `evidence {class, n,
     window, revision_current, method}` and the explanation lists what was consulted and what
     was ignored as stale or insufficient; selection is unchanged.
   - **order** — a named routing rule `evidence_order`, enabled by the user per task family and
     scope: one **discrete** ordering key, `evidence_fit` ∈ {sufficient supporting evidence on
     the current revision; none or insufficient; sufficient contradicting evidence}, placed
     **after affinity, preference and priority and before tier fit**, and applied the same way
     inside the model step among offers meeting the minimum. Only OBSERVED-sufficient and
     CONFIRMED INFERRED evidence counts.
   - **exclude** — a named routing rule `evidence_exclude` per task family and scope: eliminates a
     candidate with CONFIRMED contradicting evidence on the current revision, with a reason.
     Stale or insufficient evidence never excludes.
   Rules are ResourcePolicy-scoped (global / workspace / project / mission), versioned, and
   cited by the decisions they affect.
4. **No weighted sum** of quality, cost, latency or anything else. Each dimension is a
   constraint (eliminates with a reason) or a named discrete ordering key; cost and latency become
   keys only when an adapter reports them (P10 D15).
5. **Evidence never lowers a safety floor**: `min_model_tier` by blast radius and review
   independence stand; evidence works within them.
6. **Frozen evidence snapshot.** Every decision records `capability_snapshot`: the *values* of
   each summary and claim consulted (not only ids), the query version, `as_of_seq`, the rules in
   force. Replay uses the snapshot; later evidence never rewrites why an old execution was routed,
   and no historical execution row is ever rewritten.
7. **Fallback** is another policy-valid candidate, a bounded retry, a replan, a question to the
   human, or a stop (resource-router §7). **Escalation** is only a named rule
   `escalate_on_repeated_failure` (off by default): after the second charged failure of the same
   task, the retry's `min_model_tier` rises by exactly one tier, the decision records the rule and
   `escalated_from`, and the loop still ends at the human; never an open-ended climb.
8. **Only the user names a model** (a pin, `model_required`); the planner states requirements;
   no model decides a route. No share of real work is routed to an unevaluated model to learn:
   evaluation is an approved mission (ADR-0031 `EVALUATING`).

## Why

The directive allows evidence to inform a choice but not to override policy silently; an
annotation-first mode makes evidence visible and auditable before it can steer, and named rules
keep every effect explainable as an elimination or a key. A frozen snapshot is how usage values
are already stored (resource-router §9). OmniRoute's weighted Auto-Combo score and bandit
exploration are the patterns rejected; its neutral-prior-until-sample-floor discipline and
superpowers' bounded one-tier escalation are kept.

## Alternatives

Evidence as a weighted factor (rejected, clause E); evidence always ordering (rejected: steers
before the user has seen it); exploration traffic (rejected: spends the user's quota on real
missions without consent).

## Tradeoffs

A user must enable ordering or exclusion per family before evidence changes any choice.

## Consequences

Amends resource-router §5 (steps and keys), §7 (escalation), §8 (explanation lists evidence
consulted/ignored), and domain-model §8.6 (`task_family`, `capability_snapshot`,
`escalated_from`). ADR-0005's decision stands unchanged in kind.
