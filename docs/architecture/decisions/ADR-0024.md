# ADR-0024: Visual DNA and event-driven motion — dark and still until Archeus acts

**Amended by [ADR-0055](ADR-0055.md)** (V2, branch `v2/real`, not merged before P26: duration classes, written "does not move" rules, and one liveness exception, the core breath, to §2, §3 and §4). P19.5 (ADR-0030) · Rulebook: [ARCHEUS_V1_VISUAL_ARCHITECTURE_RECONCILIATION.md](../../design/ARCHEUS_V1_VISUAL_ARCHITECTURE_RECONCILIATION.md) §4, §21

## Decision

1. **Visual DNA.** Archeus is a constellation of real work that is dark and still until it acts.
   When real work occurs it shows *where* the work is (**activity halo**), *that* it produced
   output (**execution pulse**), *which way* work flows (**travelling marker**) and *what*
   Archeus's action touched (**the thread**, ADR-0026); when the work ends the UI is still again.
   Sequence: IDLE → ACTIVITY → FLOW → OUTPUT → SETTLED.
2. **Idle invariant.** With no live execution, no arriving change and no user input, the client
   schedules **zero** animation frames and runs **zero** animations. Gated.
3. **One motion registry** (`motion.json`, generated like `presentation.json`) is the only place
   an animation may be declared. Each entry states: name, backend trigger, duration, easing,
   concurrency cap, surfaces, reduced-motion behaviour, text/static equivalent, whether it may run
   while idle (never, except static states), and whether it may replay after a reconnect (never).
   A keyframe, WAAPI animation or rAF use not in the registry fails the build.
4. **Rules for every animation:** triggered by a backend event or a user action; finite;
   deterministic (a pure function of state and presentation time — testable with `renderAt(t)`);
   capped; interruptible (nothing waits for an animation); degrades under load; transform and
   opacity only (never `filter`, blur, blend or a paint property); `Math.random` banned in the
   client's animation, rendering, layout and presentation state (`src/graph/`, `src/state/`) —
   clarified 2026-09-30: an operational identifier such as the idempotency-key fallback in
   `data/commands.ts` is not a visual and is outside the rule; one `requestAnimationFrame` caller
   (`graph/loop.ts`).
5. **Two clocks** (after zoetrope): state is read from the record; animation ages in presentation
   time, forward only. A re-read, resync, reconnect or seek redraws state and **never replays**
   pulses, markers or threads. Halos have **hysteresis**: they appear on the first read showing
   the object live and clear only when a read shows the work ended — never on a transient
   reconnect.
6. **Signature elements and caps:** halo — static, no animation, unlimited, drawn into the static
   layer; pulse — one 240 ms opacity step per output batch, ≤ 1 per object per 2 s, ≤ 12
   concurrent on the canvas; travelling marker — one per output batch along a drawn live edge,
   ≤ 600 ms, ≤ 8 concurrent (oldest dropped), thread ink; activity chip — current action,
   TTL 2.5 s (4 s on error), ≤ 3 per row; thread draw-on — ≤ 600 ms, one at a time; presence
   orbit — ≤ 900 ms, ≤ 1 per 5 s.
7. **No fake activity.** No visual activity without an underlying event. Demo or fixture motion is
   impossible while real Core data is present.

## Why

The V1 references ask for a "living system", a "living graph", "state-aware energy" and
"light/energy"; the legacy lineage (constellation-study traits 3 and 10, stage `energy()`, brand
rule "bounded, driven by real state, and it stops") already had the concepts; P18 rejected the
*mechanisms* (perpetual loop, random phases, `sin(T)` breathing, bokeh, ambient stage), not the
concepts. Munder Difflin's "every animation should actually tell you something" and Apple's
"motion is never the only carrier of information" state the discipline.

## Alternatives

Keep V1 static apart from the 240 ms edge pulse (rejected: two executing missions look idle);
restore ambient motion (rejected: principle 5, cost, the flicker lessons).

## Tradeoffs

A registry and gates to maintain; every effect needs a text equivalent and a cap.

## Consequences

Amends P18 A8 (ADR-0030, PROPOSED). New gates in testing-strategy §7: idle invariant, registry,
caps, no-replay, reduced motion, text equivalents — each mutation-verified.
