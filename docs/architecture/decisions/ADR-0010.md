# ADR-0010: Remote access and mobile: PWA over a user-operated HTTPS tunnel

**Status:** PROPOSED · **Date:** 2026-09-23

## Decision

The phone uses the same SPA installed as a PWA, reaching Core through a user-operated HTTPS tunnel (Tailscale Serve recommended). Devices pair from a local session with one-time codes and receive scoped, hashed, revocable tokens. Push uses ntfy deep links (not built: no ntfy code exists); Web Push is deferred. Destructive approvals need a step-up PIN.

## Why

One codebase for iOS and Android with no Mac or developer subscription (spec §22). HTTPS is needed for a PWA. Tunnels avoid exposing Core publicly.

## Alternatives

Native iOS/Android apps; a hosted relay service; exposing Core on the LAN.

## Tradeoffs

Requires the user to set up a tunnel; iOS push reliability via ntfy is good but not native.

## Consequences

The Host allowlist is the listener's own `127.0.0.1:<port>` plus the tunnel hostnames the operator passes with `--remote-host`; pairing adds no hostname. `localhost` is not a second name for the local origin, and a loopback peer alone does not make a request local.
