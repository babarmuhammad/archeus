## Findings

1. archeus/core/domain/entities.py:1686-1694, archeus/core/policy/rules.py:217-223, archeus/core/application/authorization.py:1014, tools/fuzz_p20.py:75-84 and :141-152 (**Medium, blocking: D12's property**).
   - **Problem:** `PolicyRule._check` checks a boundary's keys but not its values. `check_boundary` iterates each value, so one that is not a list raises `TypeError`, and `simulate` (which catches only TypeError raised while building the action and rules) answers 500. faa53d1's title is "a malformed value inside a free-form field is a 400". `_simulated_rule` reuses `create_rule`'s checks, so it inherits this gap.
   - **Stored copy:** `create_rule` accepts the same boundary and stores it. Every later evaluation of that class on that chain then raises. That includes `simulate`, and by reading also the hook's `serve_hook`, where `manager.py:502` fails closed to `halt` for every such tool call.
   - **Scenario** (reproduced in process through `_serve` on a fresh Core at 2f93182; the same at 36160ba, so pre-existing):
     - `{"action":{"class":"write_repo","target":"a","paths":["a"]},"extra_rules":[{"scope_level":"WORKSPACE","scope_ref":"ws_global","action_class":"write_repo","decision":"ALLOW_WITHIN_BOUNDARY","boundary":{"paths":5}}]}` -> `500 internal`.
     - The same with `{"hosts":5}` or `{"branches":5}` on a `git_push` with a host and a branch, or `{"environments":5}` on a `deploy` with an environment -> 500 each. `{"paths": null}` raises the same TypeError in `check_boundary`.
     - `POST /v1/policies/rules` with a USER `write_repo` rule, `ALLOW_WITHIN_BOUNDARY`, `boundary {"paths":5}` -> 200 (stored). After that, `simulate` with a `write_repo` action -> 500, while a `read` -> 200.
   - **Why the harness cannot see it:**
     - `poke()` only ever replaces a leaf. A non-empty list is walked into, never replaced, so `boundary.paths: ['src/**']` can become `[5]` but never `5`.
     - The simulate recorded body has no `ALLOW_WITHIN_BOUNDARY` rule.
     - Experiment (scratch copy, restored): with `poke` allowed to pick any node and one AWB rule added to the simulate recorded body, the CI-sized run (budget 3000) finds simulate 500s on 4 of 11 seeds (3, 6, 8, 9).
   - **Required change:**
     - Have `PolicyRule._check` refuse a malformed boundary value: `paths`/`hosts`/`branches`/`environments` must be lists of non-empty strings, and `max_cost_band` must be one of `COST_BANDS`. Both `create_rule` and `simulate` then answer 400.
     - Pin the four bodies above in `test_H04b`, and add one `POST /v1/policies/rules` body to the free-form test.
     - Let `poke()` replace a container as well as a leaf, and add an AWB rule to the simulate recorded body, so the harness can reach this class.
     - A Q mutant on the new check.
   - **Suggested:** the same treatment for `match` values. These do not crash today, because `glob` goes through `str()`.
