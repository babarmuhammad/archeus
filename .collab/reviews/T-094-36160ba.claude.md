## Findings

1. archeus/core/application/authorization.py:1018-1024 and tools/fuzz_p20.py:55,45 (Medium).
   - **Problem:** `POST /v1/policies/simulate` still answers 500 for a malformed rule. The guard covers only construction `TypeError`s. A rule with a decision outside the vocabulary, or a non-string `expires_at`, gets through construction and then fails in the engine: `KeyError` at `policy/engine.py:41/87` (`R.STRICTNESS[...]`), and `TypeError` at `engine.py:72` (`int <= str`).
   - **Scenario** (reproduced on the archive at 36160ba, in process through `_serve`):
     - `{"action":{"class":"read","target":"x"},"extra_rules":[{"scope_level":"GLOBAL","action_class":"read","decision":"MAYBE"}]}` -> `500 internal` (`KeyError('MAYBE')`).
     - The same rule with `"decision":"ALLOW","expires_at":5` -> `500 internal` (`TypeError`).
   - **Why the fuzz cannot see it:** `SIMULATE` types `action` and `extra_rules[]` as bare `{'type':'object'}`. `example()` therefore emits `{}`, `mutate()` only adds `zz_` keys, and the "recorded corpus" is only the endpoint floor's junk bodies. Nothing ever has a real rule's keys to corrupt a value under. Seven routes have such fields: plans/{id}/edit `refs`/`inputs`, projects/{id}/constraints `spec`, knowledge/forget `selector`, resource-policies/{id} `budgets`, policies/rules `match`/`boundary`, simulate `action`/`extra_rules[]`, and automations `trigger`/`template`.
   - **Required change:**
     - Validate extra rules (and the action's fields) against the vocabulary that already exists, so these bodies are 400. Use `schemas.CREATE_RULE`'s enums or `entities.PolicyRule`'s `_CHOICES`/`ValueError` checks: decision, scope_level, action_class, outside, expires_at string-or-null, and match/boundary keys.
     - Add both bodies to `test_H04b`.
     - Seed the fuzz corpus with recorded valid bodies for the bare-object fields (at least a real rule, an action, a trigger and a template). That is what D12's "corpus of recorded inputs plus structured mutation" names, and it lets the mutation reach values.
2. tools/fuzz_p20.py:208-226 (`conservative`) and archeus/core/execution/canonical.py:67-72 (Medium).
   - **Problem:** D12's property (never less strict than the conservative class for an input it cannot parse) is asserted only for Bash commands that `shlex` cannot split and for tools outside `PARSED`. The harness generates file-tool calls whose required path is missing or not a string, and passes them. The canonicaliser classifies those permissively.
   - **Scenario** (direct calls on the archive), each `unclassified=False`:
     - `Write {}`, `Write {'file_path': ['/etc/passwd']}`, `Edit {'file_path': 5}` and `Write None` -> `write_repo` on `'.'`, inside the workspace.
     - `WebFetch {'url': ['http://evil']}` -> `web` with `host=None`, so no `host_glob` rule can match it.
     - P9 may ALLOW `write_repo`, but it never ALLOWs an unclassified action (item 83). These answers are therefore less strict than the conservative one.
   - **Reach:** in practice this depends on whether the CLI validates tool input before PreToolUse, which was not established.
   - **Required change:** pick one of two.
     - Encode the property for the parsed tools in `conservative()` and fix `_canonicalise` to match. Read/Write/Edit/MultiEdit/NotebookEdit with the required path absent or not a string, and WebFetch with a non-string url, become one unclassified `exec`. Glob/Grep/LS may keep `'.'` for an absent optional path.
     - Or narrow item 116's wording and the test's name to what is checked, and record the gap on the card for the owner.

4. archeus/core/execution/canonical.py:58-61 (Low, optional).
   - **Problem:** the fallback returns `_unclassified(str(tool))`, which carries no argv. The module's own parse-failure form for a command is `_unclassified('shell', (cmd,))`. That form keeps the command, so the action approval shows it and binds its single-use `action_hash` to it.
